# Report 202: SSRM-3D Pre-Avatar Playable World Seed, Spatial Ecology, and Avatar Spawn Lock Bridge

## Purpose

Report 202 extends the Report 201 deep-time civilization simulator into a spatial playable-world seed.

The goal is to turn public pre-avatar history into places, bodies, ecological conditions, tool objects, routes, settlement memory, and avatar spawn locking. The avatar should not enter a blank dataset. It should enter a world seed that already has spatial settlements, embodied agents, ecological context, and public constraints.

This is not complete 3D gameplay, real embodiment, real perception, real consent, subjective consciousness, or moral patienthood. It is deterministic playable-world substrate.

## Why this matters

The active project goal requires the world to be deeply created before avatar entry. Report 201 gave the world a long pre-avatar history. Report 202 starts materializing that history into a spatial seed:

- settlements become coordinates
- agents get body state
- sensory packets include vision, sound, smell, temperature, and wetness
- weather changes body warmth, wetness, fatigue, and pain
- tools become objects near settlements
- settlements connect through routes
- settlement memories bind to places
- avatar spawn remains locked until the world seed is ready

This is the first bridge where deep-time history becomes a public spatial replay surface with body and ecology channels.

## Implementation

The experiment is implemented in `experiments/ssrm_3d_pre_avatar_playable_world_seed_spatial_ecology_avatar_lock_bridge.py`.

It consumes `artifacts/ssrm_3d_pre_avatar_deep_time_civilization_simulator_bridge_state.json` from Report 201 and adds:

- spatial settlement instantiation
- ecological cycle binding
- embodied agent presence
- body sensory channels
- weather/body coupling
- tool object materialization
- route graph connectivity
- settlement memory spatial binding
- avatar spawn locking
- playable affordance seeding
- private workspace privacy
- frequency/flower spatial rhythm
- browser world-seed replay

No LLMs are called. The benchmark is deterministic for seed `20260815` and `9` world ticks.

## Spatial seed

Report 202 uses three settlement coordinates:

- `west_bench_cluster`: work-petal place
- `root_rest_hollow`: root-rest place
- `north_route_ring`: social-petal place

Each world-seed event binds a lineage to:

- settlement coordinate
- weather and resource pressure
- body energy, warmth, wetness, fatigue, pain, and movement effort
- sensory packet
- tool object
- route graph
- settlement memory
- avatar spawn lock
- playable affordance seed
- frequency rate
- flower path

## Avatar spawn lock

The avatar spawn lock has two states:

- `locked_until_spatial_world_ready`
- `eligible_after_world_seed`

The gate remains locked while the spatial seed is still forming. It becomes eligible only at the final world tick when settlements, ecology, bodies, senses, tools, routes, memory binding, weather/body coupling, and privacy are all present.

This is not real consent. It is a safety and readiness affordance for a future playable avatar controller.

## Moral and claim boundary

The experiment explicitly preserves these boundaries:

- spatial world seed is not complete 3D gameplay
- body state is not real embodiment
- sensory packet is not real perception
- avatar spawn lock is not real consent
- no subjective consciousness claim
- no moral patienthood claim
- private workspace is not debug-leaked

This boundary matters because spatial bodies and senses make the agents feel more real. The report keeps the no-consciousness and no-real-embodiment distinction explicit.

## Limitations

- The browser page is still replay, not a live controller.
- Spatial settlements are coordinates, not full 3D geometry.
- Collision, pathfinding, and avatar movement are not live yet.
- Tool objects are materialized records, not manipulable physics objects.
- Body and sensory channels are functional packets, not real perception.
- Avatar spawn lock is symbolic, not integrated into a playable input loop.

## Next gate

The next gate should be a live browser playable loop with avatar movement, spatial collision, agent proximity, and consent-aware interaction prompts.

Report 202 creates the spatial world seed. The next step is to let a browser avatar move inside it, collide with places, approach agents, see proximity prompts, and obey consent-aware affordance locks.
